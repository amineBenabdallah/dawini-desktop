Dr. Amira — System Architecture

Local AI medical assistant for Dawini Desktop

v1.0 — April 2026

1 Core Principle

Amira ALWAYS speaks through the LLM — but ONLY from Layer 1 and Layer 2 data.

She never answers from the model's own training knowledge. If no reference data is found, she says "I don't have this in my references" instead of guessing. The LLM is the voice, not the brain.

Layer 1 Doctor's Documents

PDFs, DOCX, TXT that the doctor drops into the library. Indexed into vector embeddings via LanceDB.

Algorithm: HNSW (Hierarchical Navigable Small World) — cosine similarity search, O(log n), ~5ms on 50K vectors.

Trust level: Highest — doctor's own verified references.

Examples: Dorosz 2025, Vidal, MSPRH guide ATB, university course notes, personal protocols.

Layer 2 Pre-bundled Data

Free, verified datasets shipped with the app. Loaded into memory from JSON files at startup.

Algorithm: In-memory Array.filter + String.includes (<1ms on datasets <5MB). Laws searched via substring match.

Trust level: High — official sources (WHO, MSPRH, JORA).

Examples: CIM-10 codes, lab normal ranges, vaccination calendar, tarification CNAS.

LLM The Voice

Mistral Nemo 12B (local, GGUF). Reads the references from L1+L2 and generates a natural, cited response.

Trust level: N/A — it only speaks from provided data, never from its own knowledge.

If no data found: "Je n'ai pas cette information dans mes références."

☉ Screen Context — What Gets Injected Where

The context sent to the LLM is not the same on every screen. Each screen injects only the data relevant to what the doctor is doing:

ScreenContext InjectedNOT Included
Consultation Patient (age, gender, history, current meds) + current vitals (TA, poids, temp) + motif —
Ordonnance Patient (age, weight, renal function, allergies) + current meds + current diagnostic Full consultation notes
Certificat Patient (name, age) + current consultation diagnostic + certificate type Medication list, lab results
Patient file Full patient history (all consultations, ordonnances, lab results) —
Queue triage Patient motif only (reason for visit) Medical history (patient not identified yet)
Facturation Consultation type + acts performed Patient medical data (privacy)
Dashboard Today's appointments + overdue follow-ups from DB Specific patient data
Rendez-vous Patient (if selected) + last consultation date + follow-up rules Full medical history
Free chat Current screen context (patient if one is open, nothing if not) —
Minimum data principle: Each screen sends only what the LLM needs for that specific task. Queue triage doesn't send medical history (the patient hasn't been identified yet). Facturation doesn't send diagnostics (privacy — billing staff shouldn't see clinical notes).

Amira is a separate module — she can be removed without breaking any existing functionality.

Isolation rule: Amira reads from existing modules (patient data, consultations, ordonnances) but never writes to them. She suggests — the doctor decides and acts. No existing module depends on Amira.
